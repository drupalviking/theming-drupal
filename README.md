# Theming Drupal

An open book about building Drupal themes: **Book 2** in the series, after *Developing Open Sourced Web Software with Drupal* (the site-building book, "Book 1"), and before *Drupal Module Development for Drupal 11 and 12* (Book 3, written first, in `~/websites/ru/book-rewrite`). It is written for the Drupal Open University Initiative, and for anyone to use, share, and improve.

Book 1 built **Lens & Trail**, the website of a small photography and hiking club in Edinburgh, in English and Spanish, on Drupal core and on Drupal CMS. It ended with the club's site on someone else's theme (Olivero on core, Mercury on Drupal CMS) and a promise: *Theming Drupal* is where you make your own. In this book the reader gives both sites a theme of their own:

- **The core site**: a theme generated with core's **Starterkit**, with plain modern CSS, Single Directory Components (SDC) and Twig. **No Node, no npm, no build step.**
- **The Drupal CMS site**: a theme made from **Mercury**, Drupal CMS's own theme, with Tailwind CSS and its small npm toolchain, explained and pinned, with a routine for upgrading it years later.

Why these two, and not a subtheme or a contrib base theme: `research/choosing-an-approach.md`.

The reader is someone who finished Book 1, or a front-end developer new to Drupal: they know site building and basic HTML and CSS. Everything Drupal-specific (Twig, render arrays, libraries, preprocess functions, components) is explained from the start.

## Writing

The manuscript is plain Markdown. Obsidian works well: open the repository as a vault. The settings in `.obsidian/app.json` make Obsidian write standard Markdown links and put pasted images in `manuscript/images/`.

- **Code is never typed into the manuscript.** Every listing is pulled from a tested file under `code/` (the module book's rule):

  ```markdown
  <!-- include: code/chapter04/steps/01-generate/core/lens_trail/lens_trail.info.yml -->
  <!-- include: <path> key=regions -->              one top-level YAML entry
  <!-- include: <path> function=preprocessNode -->  one PHP method
  <!-- diff: <old path> <new path> -->              what changed between two steps
  ```

  Short one-liners (a Drush command, a three-line fragment) may be inline. See `tools/build.py` for every option.
- Images: `![What the image shows](images/07-hike-card.png)`, followed by `*Figure 7.3: Caption*` on its own line. No Obsidian `![[wiki links]]`; the build fails on them.
- Notes to yourself or other authors: `%% like this %%`. They never reach `book/`.
- Numbers that go out of date: `{{ number:mercury_version }}` (the `number:` keeps them apart from Twig's `{{ }}`).
- US spelling. One line per paragraph.

Each chapter follows the same pattern as Book 1: what you'll learn, sections with "Try it" steps on the club's sites, a summary, exercises, and "Want to know more?". The details are in `.claude/skills/write-chapter/SKILL.md`.

## Building

```bash
python3 -m pip install -r requirements.txt   # once: the build needs PyYAML
python3 tools/build.py           # build book/ from manuscript/, remove files with no source
python3 tools/build.py --check   # fail if book/ is out of date
```

Run the build and commit `book/` with your manuscript changes.

### Numbers that go out of date

```bash
python3 tools/update_numbers.py --dry-run    # see what changed, write nothing
python3 tools/update_numbers.py              # write the new values into data/numbers.yml
python3 tools/build.py
```

### The test sites

The themes are tested on two DDEV sites, rebuilt from Book 1's finished sites. **Readers can do the same, without having worked through Book 1**: `tools/setup.sh` needs only DDEV and Git, clones Book 1 next to this folder if it isn't there, and makes the two sites next to this folder too. Book 1 exports them into its `sites/` folder (its `tools/export-sites.sh`: Composer files, configuration, and content as a recipe), and this book pins the Book 1 commit it builds on in `data/book1.yml`. Separate sites mean the two books never break each other's screenshots.

```bash
git clone https://github.com/drupalviking/theming-drupal.git
cd theming-drupal
tools/setup.sh                 # build lens-and-trail-theme and lens-and-trail-cms-theme from Book 1
tools/use-step.sh 04 01        # put Chapter 4's first step on the sites, as the default theme
```

When Book 1 changes a site: re-export it there and commit, put the new commit in `data/book1.yml`, delete the two sites (`ddev delete -O <name>` and the folder), run `tools/setup.sh`, put the theme back with `tools/use-step.sh`, and check the chapters' pages. Log in with `admin` / `12345`.

`PROJECT-LOG.md` ("Where we are") has their URLs and state.

## Check before publication

Facts about releases and products that change quickly. Re-check each before a release.

- Baseline dates in Chapter 3 (checked 2026-11-07 in the web-features data): `light-dark()` newly available 2024-05-13, widely available on 2026-11-13; scroll-driven animations newly available 2026-10-27; `text-wrap: balance` newly available 2024-05-13; OKLCH widely available 2025-11-09; container queries 2025-08-14; `forced-colors` 2025-03-12.
- Colorbox has no Drupal 12 release (2.2.1, `^10.2 || ^11`, maintenance fixes only, 2026-11-07); nor has PhotoSwipe (5.0.13, `^10.3 || ^11`). Chapter 3 says so.
- Olivero (contrib on Drupal 12) has no `prefers-reduced-motion` rule in its CSS, and `forced-colors` rules in several files (2026-11-07): Chapter 3's Try it relies on it.
- Chrome's developer tools: **More tools** > **Rendering** > **Emulate CSS media feature forced-colors** / **prefers-reduced-motion** (Chapter 3's Try its).
- Mercury 1.0.5 requires Drupal ^11.3 (2026-11-07): the Mercury track runs on the Drupal CMS site (Drupal 11.4) until Mercury has a Drupal 12 release.
- Core's `starterkit_theme` in Drupal 12.0.0-beta2 has no `components/` folder (2026-11-07).
- Penpot's token import format (Chapter 4's `code/chapter04/lens-and-trail-tokens.json`), read from Penpot's source on `main` (2026-11-08, `common/src/app/common/types/tokens_lib.cljc` and `token.cljc`): sets as top-level keys, `$themes` (each with `name`, `group`, `description` and `selectedTokenSets`), `$metadata` (`tokenSetOrder`, `activeThemes`, `activeSets`); `$type` names `color`, `spacing`, `borderRadius`, `borderWidth`, `fontFamilies`, `fontWeights`, `fontSizes`, `sizing`, `dimension`, `number`, `shadow`. Import replaces all of a file's tokens (Penpot's help). Font sizes in px only for now; rem is promised. Exported again on 2026-11-08 (**Tokens → Tools → Export**, Single file) as `design/tokens.json`: the same 101 tokens and descriptions, but font families come out as lists (`["Bricolage Grotesque"]`), the themes lose their descriptions and gain `id` and `isSource`, and the key order changes.
