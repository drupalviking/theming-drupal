# Theming Drupal

An open book about building Drupal themes, and the companion to *Developing Open Sourced Web Software with Drupal* (the site-building book, "Book 1"). It is written for the Drupal Open University Initiative, and for anyone to use, share, and improve.

Book 1 built **Lens & Trail**, the website of a small photography and hiking club in Edinburgh, in English and Spanish, on Drupal core and on Drupal CMS. It ended with the club's site on someone else's theme (Olivero on core, Mercury on Drupal CMS) and a promise: *Theming Drupal* is where you make your own. In this book the reader gives both sites a theme of their own:

- **The core site**: a theme generated with core's **Starterkit**, with plain modern CSS, Single Directory Components (SDC) and Twig. **No Node, no npm, no build step.**
- **The Drupal CMS site**: a theme made from **Mercury**, Drupal CMS's own theme, with Tailwind CSS and its small npm toolchain, explained and pinned, with a routine for upgrading it years later.

Why these two, and not a subtheme or a contrib base theme: `research/choosing-an-approach.md`.

The reader is someone who finished Book 1, or a front-end developer new to Drupal: they know site building and basic HTML and CSS. Everything Drupal-specific (Twig, render arrays, libraries, preprocess functions, components) is explained from the start.

## Writing

The manuscript is plain Markdown. Obsidian works well: open the repository as a vault. The settings in `.obsidian/app.json` make Obsidian write standard Markdown links and put pasted images in `manuscript/images/`.

- **Code is never typed into the manuscript.** Every listing is pulled from a tested file under `code/` (the module book's rule):

  ```markdown
  <!-- include: code/chapter04/steps/01-generate/core/lens_trail/lens_trail.info.yml -->
  <!-- include: <path> key=regions -->              one top-level YAML entry
  <!-- include: <path> function=preprocessNode -->  one PHP method
  <!-- diff: <old path> <new path> -->              what changed between two steps
  ```

  Short one-liners (a Drush command, a three-line fragment) may be inline. See `tools/build.py` for every option.
- Images: `![What the image shows](images/07-hike-card.png)`, followed by `*Figure 7.3: Caption*` on its own line. No Obsidian `![[wiki links]]`; the build fails on them.
- Notes to yourself or other authors: `%% like this %%`. They never reach `book/`.
- Numbers that go out of date: `{{ number:mercury_version }}` (the `number:` keeps them apart from Twig's `{{ }}`).
- US spelling. One line per paragraph.

Each chapter follows the same pattern as Book 1: what you'll learn, sections with "Try it" steps on the club's sites, a summary, exercises, and "Want to know more?". The details are in `.claude/skills/write-chapter/SKILL.md`.

## Building

```bash
python3 -m pip install -r requirements.txt   # once: the build needs PyYAML
python3 tools/build.py           # build book/ from manuscript/, remove files with no source
python3 tools/build.py --check   # fail if book/ is out of date
```

Run the build and commit `book/` with your manuscript changes.

### Numbers that go out of date

```bash
python3 tools/update_numbers.py --dry-run    # see what changed, write nothing
python3 tools/update_numbers.py              # write the new values into data/numbers.yml
python3 tools/build.py
```

### The test sites

The themes are tested on two DDEV sites, copies of Book 1's final sites, so the two books never break each other's screenshots:

```bash
tools/setup.sh                 # make lens-and-trail-theme and lens-and-trail-cms-theme
tools/use-step.sh 04 01        # put Chapter 4's first step on the sites, as the default theme
```

`PROJECT-LOG.md` ("Where we are") has their URLs and state.

## Check before publication

Facts about releases and products that change quickly. Re-check each before a release.

- Core's `starterkit_theme` in Drupal 12.0.0-beta2 has no `components/` folder (2026-11-07).
